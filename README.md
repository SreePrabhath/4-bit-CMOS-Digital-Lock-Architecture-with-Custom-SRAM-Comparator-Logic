# 🔐 Transistor-Level 4-bit Digital Lock System (Cadence Virtuoso)

A 4-bit digital lock designed **fully at transistor level** in Cadence Virtuoso. Two passwords are stored in **6T SRAM cells**, the user input is generated by **Johnson counters**, and two **CMOS comparators** check the input against each stored password. The lock opens only when **both** comparisons match.

## 📌 Features

- Two 4-bit passwords stored statically in **6T SRAM** (with an OTA-based **sense amplifier** for read-out)
- Two **4-bit Johnson counters** (built from C²MOS flip-flops) used as the user-input source, each starting from a different state
- Two **4-bit comparators** built from XNOR, AND and OR gates (equal, greater-than, less-than outputs)
- Final **AND gate** gives the UNLOCK signal; an OR of the mismatch signals gives the LOCK signal
- Every block (inverter, AND2/3/4, OR4, XNOR, flip-flop, SRAM, sense amp) is designed with individual transistors, with its own schematic, symbol and simulation

## 🧩 System Overview

```
 Password A (6T SRAM) ─┐
                       ├─► 4-bit Comparator 1 ─► UNL1 ─┐
 Johnson Counter 1 ────┘                               │
                                                       ├─► AND ─► UNLOCK
 Password B (6T SRAM) ─┐                               │
                       ├─► 4-bit Comparator 2 ─► UNL2 ─┘
 Johnson Counter 2 ────┘
                         mismatch signals (L1..L4) ─► OR ─► LOCK
```

**Lock logic:** `UNLOCK = MatchA AND MatchB`

## 🧱 Block-Level Design

| Block | Description |
|---|---|
| Inverter, AND2/3/4, OR4 | Static CMOS gates, the base library for everything else |
| XNOR (2-input) | Bitwise equality check: `Ei = XNOR(Ai, Bi)` |
| 4-bit Comparator | `A = B` = E3·E2·E1·E0, plus A>B and A<B logic |
| C²MOS Flip-Flop | Clock-skew-insensitive storage element for the counters |
| Johnson Counter (×2) | 4-bit twisted-ring counter, different start states |
| 6T SRAM cell | Cross-coupled inverters + access transistors, stores 1 bit |
| Sense Amplifier (OTA) | Reads the SRAM bit lines and gives a clean logic output |
| Password A / B | 4 × (6T SRAM + sense amp) each |

**Comparator equations**

```
Ei     = XNOR(Ai, Bi)
A = B  = E3·E2·E1·E0
A > B  = G3 + E3·G2 + E3·E2·G1 + E3·E2·E1·G0      (Gi = Ai·B̅i)
A < B  = L3 + E3·L2 + E3·E2·L1 + E3·E2·E1·L0      (Li = A̅i·Bi)
```

## 📊 Results

- Each block was simulated on its own (comparator, C²MOS FF, Johnson counters, sense amp, SRAM + sense amp).
- In the full-system transient run, **UNL1 and UNL2 go high together** when both counters match their stored passwords, which gives a **UNLOCK pulse** (around 10–12 µs in the report waveforms).
- At that same moment the **LOCK** signal goes low, and it stays high otherwise, so the lock opens only on a double match.

## ▶️ How to Reproduce

1. Open the library in **Cadence Virtuoso** with the GPDK 090 PDK installed.
2. Open the top-level cell `Digital_Lock_MainBlocks` (or the complete integrated schematic).
3. In ADE, set VDD = 1.8 V, clock = 500 kHz, temperature = 27 °C.
4. Run a **transient** analysis for about 25 µs and plot `UNLOCK_` and `LOCK_`.
